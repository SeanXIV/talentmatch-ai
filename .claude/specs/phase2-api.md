### Entities (match V1 exactly; ddl-auto=validate)
- `@Id @GeneratedValue(strategy = GenerationType.UUID) UUID id`; timestamps `Instant`, `hibernate.jdbc.time_zone=UTC`.
- created_at/updated_at: `@Column(insertable=false, updatable=false)` + Hibernate `@Generated(event = INSERT)` (created_at) / `@Generated(event = {INSERT, UPDATE})` (updated_at): read-only, DB-maintained, re-read after write.
- text columns (summary, description, ai_explanation): `@Column(columnDefinition = "text")`. score: `double`.
- @Table names candidate, job, skill, candidate_skill, job_skill, job_match.
- CandidateSkill: `@EmbeddedId CandidateSkillId(candidateId, skillId)` (@Embeddable, Serializable, equals/hashCode); `@ManyToOne(fetch=LAZY) @MapsId("candidateId") Candidate candidate`; same for skill; `Integer yearsExperience`. JobSkill same with `boolean required`.
- Candidate.skills / Job.skills: `@OneToMany(mappedBy, cascade=ALL, orphanRemoval=true) Set<...>`.
- JobMatch: candidateId/jobId as plain UUID columns; validation & reads only; all writes via JDBC upsert.
- equals/hashCode by id.

### ScoringEngine (pure)
```java
public final class ScoringEngine {
  public ScoringEngine(ScoringWeights weights)
  public static boolean isMatchable(Collection<JobRequirement> reqs)        // !reqs.isEmpty()
  /** @throws IllegalArgumentException if reqs empty or duplicate skillIds */
  public MatchEvaluation evaluate(List<JobRequirement> reqs, Collection<CandidateSkillFact> candidateSkills)
}
```
- Required = weights.required pts, nice = weights.niceToHave; earned = points for skills the candidate has; score = earned/(double)max clamped [0,1]. Extra candidate skills ignored. Years never affect score, only shown on matched hits.
- All lists sorted by name (case-insensitive, Locale.ROOT), then skillId.
- Summary (parts joined "; ", then "."). R = required count, r matched, N nice count, n matched:
  - R>0: "Matches {r} of {R} required skill(s)"; if r<R add "missing: " + join(", ", missingRequired names)
  - N>0 && R>0: add "{n} of {N} nice-to-have"
  - N>0 && R=0: first part "Matches {n} of {N} nice-to-have skill(s)"
  - "skill" singular when count is 1.
  - Examples: `Matches 4 of 5 required skills; missing: Kubernetes; 1 of 2 nice-to-have.` / `Matches 0 of 1 required skill; missing: Java.` / `Matches 2 of 3 nice-to-have skills.`

## 4. V2 migration `src/main/resources/db/migration/V2__skill_link_staleness.sql` (exact)
```sql
-- V2__skill_link_staleness.sql — make skill-link changes visible to match staleness.
-- Any real INSERT/UPDATE/DELETE on candidate_skill / job_skill bumps the parent's
-- updated_at, so job_match.computed_at < max(candidate.updated_at, job.updated_at)
-- detects skill changes. Statement-level triggers with transition tables: one parent
-- UPDATE per statement; statements touching zero rows (no-op ETL reruns) change nothing.
-- The "IS DISTINCT FROM now()" guard skips parents already touched in this transaction.

CREATE FUNCTION touch_candidate_from_links() RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
    IF TG_OP = 'INSERT' THEN
        UPDATE candidate SET updated_at = now()
         WHERE id IN (SELECT candidate_id FROM new_links)
           AND updated_at IS DISTINCT FROM now();
    ELSIF TG_OP = 'UPDATE' THEN
        UPDATE candidate SET updated_at = now()
         WHERE id IN (SELECT candidate_id FROM new_links
                      UNION SELECT candidate_id FROM old_links)
           AND updated_at IS DISTINCT FROM now();
    ELSE
        UPDATE candidate SET updated_at = now()
         WHERE id IN (SELECT candidate_id FROM old_links)
           AND updated_at IS DISTINCT FROM now();
    END IF;
    RETURN NULL;
END;
$$;

CREATE FUNCTION touch_job_from_links() RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
    IF TG_OP = 'INSERT' THEN
        UPDATE job SET updated_at = now()
         WHERE id IN (SELECT job_id FROM new_links)
           AND updated_at IS DISTINCT FROM now();
    ELSIF TG_OP = 'UPDATE' THEN
        UPDATE job SET updated_at = now()
         WHERE id IN (SELECT job_id FROM new_links
                      UNION SELECT job_id FROM old_links)
           AND updated_at IS DISTINCT FROM now();
    ELSE
        UPDATE job SET updated_at = now()
         WHERE id IN (SELECT job_id FROM old_links)
           AND updated_at IS DISTINCT FROM now();
    END IF;
    RETURN NULL;
END;
$$;

-- PostgreSQL forbids transition tables on multi-event triggers: one trigger per event.
CREATE TRIGGER trg_candidate_skill_touch_ins AFTER INSERT ON candidate_skill
    REFERENCING NEW TABLE AS new_links
    FOR EACH STATEMENT EXECUTE FUNCTION touch_candidate_from_links();
CREATE TRIGGER trg_candidate_skill_touch_upd AFTER UPDATE ON candidate_skill
    REFERENCING OLD TABLE AS old_links NEW TABLE AS new_links
    FOR EACH STATEMENT EXECUTE FUNCTION touch_candidate_from_links();
CREATE TRIGGER trg_candidate_skill_touch_del AFTER DELETE ON candidate_skill
    REFERENCING OLD TABLE AS old_links
    FOR EACH STATEMENT EXECUTE FUNCTION touch_candidate_from_links();

CREATE TRIGGER trg_job_skill_touch_ins AFTER INSERT ON job_skill
    REFERENCING NEW TABLE AS new_links
    FOR EACH STATEMENT EXECUTE FUNCTION touch_job_from_links();
CREATE TRIGGER trg_job_skill_touch_upd AFTER UPDATE ON job_skill
    REFERENCING OLD TABLE AS old_links NEW TABLE AS new_links
    FOR EACH STATEMENT EXECUTE FUNCTION touch_job_from_links();
CREATE TRIGGER trg_job_skill_touch_del AFTER DELETE ON job_skill
    REFERENCING OLD TABLE AS old_links
    FOR EACH STATEMENT EXECUTE FUNCTION touch_job_from_links();
```
Rationale: DB triggers catch both writers (ETL bypasses the API); reuses updated_at (owner's staleness definition); statement-level avoids N parent updates. V1 set_updated_at() also fires on the parent (harmless). Skill delete cascades to links → fires triggers.
ETL interaction (loader.py): no-op rerun → conditional DO UPDATE updates 0 rows, prune deletes 0 → empty transition tables → nothing bumped. First load: parents inserted in same tx → guard skips. Changed/pruned link → parent bumped. ETL stats unaffected (own RETURNING). A link UPDATE that changes nothing still bumps — ETL never issues one; API must diff links.
Follow-up (tester): tests/etl/conftest.py must apply all V*.sql sorted by version. CI ETL job already applies V2 (psql, sort -V).

## 6. Matching & caching
Stale: job_match row missing or `computed_at < GREATEST(candidate.updated_at, job.updated_at)`:
```sql
SELECT c.id FROM candidate c
LEFT JOIN job_match m ON m.candidate_id = c.id AND m.job_id = :jobId
WHERE m.id IS NULL OR m.computed_at < GREATEST(c.updated_at, :jobUpdatedAt)
```
GET flow (one read-write tx, READ COMMITTED): load job (404) → load requirements (job_skill JOIN skill) → empty ⇒ NOT MATCHABLE, no writes → targets = regenerate ? all candidates : stale set → if non-empty: `SET LOCAL lock_timeout='10s'`; `pg_advisory_xact_lock(hashtextextended('job_match:'||jobId,0))`; re-run target query; facts = candidate_skill WHERE skill_id = ANY(:reqIds) [AND candidate_id = ANY(:targets)] (1 query); evaluate in memory; single upsert → ranked page + count → facts for page candidates → evaluate → breakdown → COMMIT.
Upsert (arrays via Connection.createArrayOf("uuid"/"float8"), chunk 5000):
```sql
INSERT INTO job_match (candidate_id, job_id, score, computed_at)
SELECT u.c, :jobId, u.s, now() FROM unnest(:cids::uuid[], :scores::float8[]) AS u(c, s)
ON CONFLICT (candidate_id, job_id) DO UPDATE
   SET score = EXCLUDED.score, computed_at = EXCLUDED.computed_at
```
computed_at always advances; ai_explanation untouched.
Ranked page:
```sql
SELECT m.candidate_id, c.full_name, m.score, m.computed_at, m.ai_explanation
FROM job_match m JOIN candidate c ON c.id = m.candidate_id
WHERE m.job_id = :jobId AND m.score >= :minScore
ORDER BY m.score DESC, c.full_name ASC, c.id ASC
LIMIT :limit OFFSET :page * :limit
```
+ matching count(*).
Notes: breakdown computed at read time (not stored); use cached score, WARN if engine differs. Advisory lock serializes per job; lock timeout → 503 MATCHES_BUSY. Known race (sub-second, edit tx started before recompute read but committed after) → document in PRODUCTION_READINESS. recomputeJob(jobId, force): lock → targets → facts → evaluate → upsert; SkippedNoSkills / SkippedJobDeleted. Constant query count per job; @EntityGraph(skills, skills.skill) for detail, projections for lists. full_name ordering uses DB default collation.
